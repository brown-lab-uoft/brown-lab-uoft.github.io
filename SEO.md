# SEO conventions

How this site handles search/social metadata, so it stays consistent as pages get added.

## Per-page front matter

Every page in `_pages/` should set:

```yaml
---
title: "Page Title"
permalink: /page-path/
description: "One or two sentences, unique to this page, with the actual terms someone
  would search for. This becomes the <meta description>, og:description, and
  twitter:description — it's your ad copy in search results."
---
```

Do **not** set `sitemap: false` unless the page genuinely shouldn't be indexed (utility
pages like `404.md`, or a page you're deliberately keeping unlisted). Every real content
page should be in the sitemap — that flag being set on *every* page was the site's biggest
SEO problem before this pass; see `docs/AUDIT.md`.

Optional: `image: some-filename.png` (a file under `images/`) overrides the default
`og:image`/`twitter:image` for that page. Without it, pages fall back to `images/logo.png`.
If you want a page-specific social preview (e.g. a paper's figure, an event photo), add
that file under `images/` and set `image:` in front matter.

If a page doesn't set `description`, it falls back to the sitewide `description` in
`_config.yml` — but that fallback is meant to be a last resort, not the norm. A page
without its own description is a page that looks identical to every other page in Google
search results.

## Structured data (JSON-LD)

`_includes/head.html` emits one JSON-LD block per page: a `WebSite`/`WebPage` wrapping a
`Person` (you) with two `affiliation` entries (Leslie Dan Faculty of Pharmacy, Acceleration
Consortium) and a `sameAs` list built from `_config.yml`'s `links:` block. If you add a new
external profile (e.g. a new ORCID-adjacent ID, a Bluesky/Mastodon account), add it to
`links:` in `_config.yml` and wire it into the `sameAs` array in `head.html` — don't
duplicate the block per page.

## What's still on the TODO list (not done in this pass)

- **`jekyll-seo-tag`**: the `<head>` meta/OG/Twitter tags are still hand-rolled rather than
  generated by the `jekyll-seo-tag` plugin. Hand-rolled works, but adopting the plugin would
  remove some maintenance burden. Deliberately left out of this pass to keep the diff
  reviewable — worth its own follow-up PR.
- **`ScholarlyArticle` JSON-LD per publication**: `/publications/` still renders as a plain
  bibliography with no structured data per entry. Would need field-mapping work in
  `_layouts/bibtemplate.html` against jekyll-scholar's exposed BibTeX fields.
- **A real 1200×630 OG image**: the fallback social-share image is `images/logo.png`
  (roughly square), which is why `twitter:card` is set to `summary` rather than
  `summary_large_image`. Once a proper wide banner asset exists, update the fallback and
  switch the card type in `_includes/head.html`.

## Manual steps (not something a commit can do)

- **Google Search Console**: verify the domain and submit the sitemap
  (`https://brown-lab-uoft.github.io/sitemap.xml`) once this is live — nothing here does
  that for you.
- **Google Analytics**: `analytics.google_id` in `_config.yml` is blank. Set it if you want
  traffic data; the script that reads it already exists in `_includes/analytics.html`.
